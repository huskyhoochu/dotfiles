# 사례 — 같은 원리, 세 산출물

세 산출물은 겉모양이 다르지만 산문 요구를 기계가 결정적으로 판정하는 값으로 바꾼다는 점에서 같은 일을 했다. 설계 중 막힌 결정과 같은 모양의 행을 찾아 참고한다.

- **선언 엔진**: 에이전트 규칙(AGENTS.md 의 산문)을 선언으로 바꿔 편집·커밋마다 판정하는 엔진 (polydeukes).
- **계약 패키지**: 드라이버와 대시보드가 공유하는 그래프·저널 계약 (gem12-agents `packages/graph-contract`).
- **호스트 IR**: Forgejo·GitHub 차이를 흡수하는 Git 호스트 중간 표현 (gem12-agents `docs/prd/decouple/n02-git-host-ir.md`, ADR 0004).

## 원리 1. 축과 레코드

| 산출물 | 결정 |
|---|---|
| 선언 엔진 | 증거 축(change / actor / world / history)을 저자가 쓰지 않는다. 선언의 `source` 이름에서 도출하고, 메커니즘마다 허용 형상과 대조해 잘못된 조합을 실행 전에 거부한다. |
| 계약 패키지 | `'session-started'` 대신 `{ subject, event }`. 거절은 `{ reason, of }`. 트리식 파생 어휘에서 뿌리 낱말을 바꾸자 호스트 라벨과 SSE 이벤트 이름까지 끌려간 사고가 이 결정의 계기다. |
| 호스트 IR | `HostEvent = { subject, event, ref }`, `Ref = { system, key, display }`. 호스트마다 다른 식별자(번호·id·sha)를 `Ref` 한 모양으로 받는다. |

## 원리 2. 닫힌 자리와 열린 자리

| 산출물 | 결정 |
|---|---|
| 선언 엔진 | 관계 7 개와 결합자 3 개를 튜플로 닫는다. 추출 단계는 엔진 릴리스로만 늘고, 모르는 이름은 거부한다. |
| 계약 패키지 | 공유 축은 `as const` 로 닫는다. `coached`, `superseded`, `unfit` 처럼 한 맥락에서만 참인 낱말은 그 맥락 어휘에 두고 승격 규칙으로만 축에 올린다. |
| 호스트 IR | 판정 필드는 required, 기록 필드는 extensible(`{ kind: 'unknown', native }`). |

## 원리 3. 경계 코드표

| 산출물 | 결정 |
|---|---|
| 선언 엔진 | 에이전트 어댑터가 호스트 도구 이름(`Edit`, `apply_patch`, `write_file`)을 공통 입력으로 번역해 코어에서 지운다. Codex `apply_patch` 가 라우팅에서 빠져 `passed` 로 기록된 사고가 있었다. 번역 누락은 `unattributed` 로 드러나야 한다. |
| 계약 패키지 | `codeTable` 이 충돌 시 생성 단계에서 throw, 역표는 생성. 저장 코드는 동결(ADR 0003). |
| 호스트 IR | `Resolves #N`, 서명 헤더, 머지 필드명은 어댑터 코드표 안에만. 드라이버는 `propose`, `merge`, `settle` 같은 의도만 말한다. |

## 원리 4. 판정하지 못한 것은 통과가 아니다

| 산출물 | 결정 |
|---|---|
| 선언 엔진 | `judge = relate ∘ extract`. 관계는 위반 원소 목록을 돌려준다. `skipped` ≠ `passed`, `unattributed` ≠ verdict. 표현할 수 없는 약속은 `draft`. SDK 결과는 `upheld / blocked / unjudged`. |
| 계약 패키지 | 저널은 관측 기록이고 판정하지 않는다(ADR 0001). 진실은 체크포인트에 있다. Verdict, Claim, Evidence 는 서로 다른 낱말. |
| 호스트 IR | 지킬 수 없는 의도는 capability 로 미리 밝힌다. `unknown` 은 판정에 쓰지 않는다. 기존 클라이언트가 CI 보고 0 건을 `none` 으로 읽고 머지 게이트가 `none` 을 통과로 처리한 결함이 IR 설계의 직접 동기다. |

## 원리 5. 반증 신호

| 산출물 | 결정 |
|---|---|
| 선언 엔진 | 규칙 유형 대응표(○△◐✗)로 커버리지를 잰다. 측정 결과 관계 하나(`Within`)를 지웠다. 실시간 차단이 나쁜 편집을 막은 측정 사례가 없어 기본값을 `advise` 로 내렸다. |
| 계약 패키지 | ADR 마다 뒤집기 신호. 예: "같은 뜻을 내는 레코드가 둘 이상 생기면". |
| 호스트 IR | 완료 정의는 "코어의 호스트 이름 grep 0 건". 반증 신호는 "새 호스트 때문에 드라이버를 고쳐야 했다면 그 개념은 축이 아니었다". |

## 원작자 저장소에도 남은 위반 (리뷰 연습용)

규율은 손으로만 지켜지면 샌다. 같은 저장소에서 발견된 위반이다.

- 역할 이름에 `-retry` 를 이어 붙여 새 역할 값을 만든다 → 시도 횟수는 별도 필드.
- `` `not-${OUTCOME.succeeded}` `` 로 부정 값을 조립한다 → 결과 축에 실패 값을 따로 둔다.
- 트래커 상태 축의 `closed` 를 사유 자리에 재사용한다 → 사유 축 값.
- 이슈 이벤트 `stopped / resumed` 와 IR `closed / reopened` 가 같은 사건의 두 철자다 → 하나를 축으로, 나머지는 경계 코드표.
